- Calendar entries link to the existing item detail route and use the shared warranty date utilities, so all views calculate the same deadlines.
- Warranty color markers and their legend share WarrantyMarker across the calendar and add-item selectors; colors use global semantic tokens to keep presentation consistent without changing saved durations.
- First-year reminders are computed once per item from its purchase date with the shared firstYearReminder utility, independent of warranty durations and existing pre-expiry alert preferences.
- Optional store and brand warranties use separate year-valued fields and the shared itemWarranties utility for deadlines; the existing primary warranty remains distinct to preserve saved durations and letter semantics.
- Object photos live in a separate private item-photos bucket under item-ID folders with can_access_item policies, keeping photos separate from receipt OCR and enforcing the same household access.
- Problem reporting opens the letter editor on the item detail page; it does not assert eligibility or save a claim automatically.
- Replacement letters are explicitly saved on the item as JSON; return-flow utilities require a saved letter and persisted sent date before exposing tracking, so household views and reloads share the same state.
- Letter generation uses the selected warranty's deadline and recipient; legal conformity rules apply only to the legal template, while store and brand templates defer to their commercial warranty contracts.
- Receipt OCR is dynamically loaded in browser actions only; extracted text is stored as a text sidecar in the same private item folder to preserve household access restrictions.
- Secondary content on the item page and in the add-item form is grouped behind src/components/Rubrique.tsx, a small controlled disclosure, instead of Radix Accordion/Collapsible: Radix's presence machinery makes jsdom renders seconds slower and test timeouts flaky.
- Upcoming-deadline lists, item search matching and the démarches step guide come from src/lib/deadlines.ts, built on the shared warranty utilities, so calendar, list and item page stay consistent.
- Plan-gated exports are generated by the authenticated /api/exports/$type route with RLS-scoped queries, so direct requests enforce the same plan access as the UI.
- Family invitations use single-recipient expiring tokens and authentication magic links; revocation, member removal and item attribution are enforced by database rules rather than only hidden controls.
- Warranty reminder emails use each member’s lead-time preference and an authenticated daily callback, with per-member/item/date idempotency keys instead of email queues so retries do not duplicate alerts.
- Let dependency subpaths resolve through their package exports without global entities aliases, so different parser versions use their compatible decoder.
